# 派活 第七轮体验走查（2026-11-24）· 商业级标准

**范围**：`ux/audit-high-priority-fixes` @ `d84f859`（前六轮修完后的最新版）。用 `git archive` 导出到临时目录，本机 `127.0.0.1:8957` 起服务，一次性测试库，外部请求全部拦截，未配大模型（要调模型的结果页没跑）。
**数据**：平台开「王记火锅」（餐饮，300 点）和「小美茶饮」（0 点）；老板 wangji 建 3 家店，店长 laowang、店员 xiaoli / xiaozhang、总监 zongjian；派 5 件活，覆盖在做、逾期、已交等审核、被打回、已通过五种状态。
**方式**：无头浏览器把四个角色的每一页截图（桌面 1440×900 共 44 页，手机 390×844 共 20 页），逐张看图 + 导出页面文字核对。前六轮已验证的主流程（开企业 → 建店 → 开账号 → 派活 → 交差 → 打回 → 通过）这轮不重复点，重点看六个维度里前几轮没覆盖到的：**跨页面数字是否自洽、信息架构、视觉层级、组件一致性**。

严重程度：**高** = 让人做出错误判断或以为数据丢了；**中** = 明显增加理解成本，或拉低"像正式商业产品"的观感；**低** = 打磨项。

## 一、高优先级（已修，见第五节）

| 编号 | 维度 | 问题 | 证据 |
|---|---|---|---|
| H7-1 | 反馈机制 | **今天页漏报逾期**。「今天的门店」写「逾期 0」，实际有 1 件派给店员的活已逾期 3 小时。老板每天第一眼看的页面说"没事"，而驾驶舱说"有 1 件事已经逾期"。 | `o-d-home` vs `o-d-cockpit` |
| H7-2 | 信息架构 | **老板看板不算店员的活**。「本期新建 0 / 正在执行 0 / 等您拍板 0 / 逾期 0」，同一时间驾驶舱是「派出 5 件、店员交差 3 件、逾期 1 件、等您拍板 2 件」。两块看板放在同一个「门店」入口下，数字互相打架。 | `o-d-boss` vs `o-d-cockpit` |
| H7-3 | 信息架构 | **「派出去的活」是空的**。副标题「您派出去的活都在这里」，但只列 AI 任务；已派 5 件活给店员，这页全是 0、写「还没有任务」，像数据丢了。 | `o-d-tasks` |
| H7-4 | 视觉层级 | **门店排行给最差的店发金牌**。唯一有数据的店 0 分、红字「要盯一下」，却是金色圆牌「1」；驾驶舱写「No.1 王记火锅·春熙路店」。名次和警示同时出现，信号相反。 | `o-d-store-rank`、`o-d-cockpit` |
| H7-5 | 组件一致性 | **「逾期」徽标是蓝的**。老板端任务卡「逾期」和「待做」同一种蓝色胶囊（卡片边框是红的），店员手机端「已逾期」是红的。同一个状态两种颜色。 | `o-d-staff-tasks` vs `st-m-staff` |
| H7-6 | 组件一致性 | **中文里混半角标点**，几乎每页都有：「把活派给店里的真人,店员用手机拍照交差,您(或店长)看照片…」「下达任务(内容)」「按月对账(近半年)」「游客参观(只看不用)」。单看是小事，全站都有就是"没人校对过"的观感。 | 多页 |
| H7-7 | 反馈机制 | `#/delivery` 不带任务号打开，显示原始报错「提交的内容格式不对(path.job_id)」。 | `o-d-delivery` |

H7-1/2/3 是同一个根因：产品里有两套"活"——交给 AI 专家的任务、派给店员的任务——两套数据各算各的，页面命名却都叫"派活 / 任务"。本轮先把数字和入口对齐；彻底解决见下面 M7-1。

## 二、中优先级（M7-1 至 M7-18 已做，见第五节）

### 信息架构
- **M7-1 把"两套活"在命名和入口上分清**。现状：「派活」中转页 7 张卡片平铺，AI 的 5 张、店员的 1 张、统计 1 张混在一起；「派出去的活」「老板看板」只管 AI。方案：「派活」页分两段——**派给店里的人**（派给店员、店员在做的活）和**交给 AI 专家**（下达内容任务、找行业专家、多位专家商量、协同小队、AI 派出去的活、AI 专家产出）；「派出去的活」改名「交给 AI 的活」。改动：`app.js` 的 dispatch hub 配置和 `ROUTE_LABELS`，约半天。
- **M7-2 三块看板合并成一块**。「门店」下有数据驾驶舱、老板看板、门店排行三个入口，内容重叠（驾驶舱里已经有门店表现和等您拍板）。老板看板首屏 7 张 KPI 卡有 3 张是「—」，下面 14 天表格全是 0。方案：驾驶舱作为唯一经营看板；老板看板里独有的「AI 专家干了什么」并入驾驶舱「AI 专家产出」；门店排行保留为驾驶舱「门店表现」的下钻页；老板看板入口下线或 301 到驾驶舱。约 1–2 天。
- **M7-3 账号只有登录名，没有姓名**。所有地方都显示 `xiaoli`、`laowang`：任务卡、通知「xiaoli 交了…」、驾驶舱账号表。真实门店里老板认的是"小李""王店长"。方案：`users` 加 `display_name`，建账号表单加「姓名」（必填，登录名可自动生成拼音），全站显示「小李（店员）」。涉及库表迁移，约 1–2 天，建议排在最前。
- **M7-4 修改密码放在「团队与权限」页底**。个人事项和团队管理混在一页；店长/店员找不到。方案：移到「我的」页顶部账号卡片里，团队页只留团队。
- **M7-5 平台管理员的导航和老板一样**（今天 / 派活 / 门店 / 获客 / 我的），其中派活、门店、获客对平台方没有意义。方案：root 账号导航换成「工作台 / 企业 / 后台 / 我的」。
- **M7-6 套餐页顺序**。从上到下是余额 → 购买申请（空）→ 1 点能做什么 → 按月对账 → 点数明细 → 价目表 → **套餐**。想买的人要滑过两屏账单才看到套餐。方案：余额卡右侧放「充点 / 升级套餐」主按钮锚到套餐；账单类（对账、明细）收进「账单」页签。

### 操作效率
- **M7-7 截止时间只写绝对日期**「截止 11-24 20:44」。方案：两天内写「今天 20:44 / 明天 16:44」，逾期写「已逾期 3 小时」（店员手机端也一样）。一个公共格式化函数即可。
- **M7-8 中转页只是目录**。派活、门店、获客、我的四个页面都是卡片目录，卡片上没有任何实时信息，下半屏全空。方案：卡片右上角带数字（派给店员「1 等审核 · 1 逾期」、开闭店清单「0/42 项」、定时发布「今天 2 条」），让目录页本身就能回答"哪里有事"。
- **M7-9 任务卡每件都平铺 4 个控件**（改派给…下拉、催一下、取消这件、经过）。方案：只留「催一下」，其余收进「⋯」；逾期的把「催一下」做成主按钮。

### 反馈机制
- **M7-10 清单页数字单位不一致**。顶部「待完成 6」数的是清单份数，下面每家店「0/14 项」数的是清单项。方案：顶部改成「0/42 项」或标明「6 份清单」。
- **M7-11 零值写法**「累计消耗 −0」「消耗 −0」。零不带负号；没有数据写「—」。
- **M7-12 今天页问候的日期取自浏览器，店员端取自服务器北京时间**。跨时区或手机时间不准时两端日期不一样。统一用服务器时间。

### 视觉层级与组件一致性
- **M7-13 三套视觉语言**。主站是奶油底 + 2–3px 粗黑边 + 硬投影 + emoji；数据驾驶舱是深蓝头 + 细边 + 彩色侧条；老板看板是墨绿头。方案：定一份设计令牌（颜色、圆角、边框粗细、阴影、间距、字号各一组），驾驶舱的密度和克制度更接近商业产品，建议主站向它靠：边框 2–3px → 1px，硬投影 → 轻阴影，保留暖色调和吉祥物作为品牌记忆点。这是本轮之后提升"商业感"投入产出比最高的一项，约 3–5 天。
- **M7-14 用 emoji 当图标**。各系统渲染不一样（Windows / 安卓差别大），在按钮里只有 12px 看不清，黄色主按钮上的 ✨ 基本隐形。方案：导航和按钮换成一套线性 SVG 图标（如 Lucide，MIT 许可，可内联），emoji 只留在文案和空状态插画里。
- **M7-15 控件高度不统一**。同一行里下拉框 44px、按钮 30px；筛选区的下拉框又比按钮高一截。统一成 sm 32 / md 40 两档。
- **M7-16 手机端表格变卡片后重复表头**。套餐页价目表每一行都重复「做什么 / 消耗」两个标签，3 行占一屏；「充值」徽标被拉成整行宽。方案：手机端价目表用两列列表（左事项右点数），徽标 `width:fit-content`。
- **M7-17 「数字员工」和「AI 专家」混用**。登录页标语、团队页、品牌知识包写「数字员工」，其余写「AI 专家」。选一个（建议「AI 专家」），全站替换。
- **M7-18 登录页定位**。标语「老板会派活，数字员工去干活 · 11 大连锁行业·专属决策员工听您调遣」讲的是 AI 员工；README 和实际主流程是「门店 AI 督导：派活、拍照交差、盯整改」。首屏一句话建议和主流程对齐。

## 三、低优先级
- 巡店页副标题「区域经理巡店 · …巡店经理会标出可见问题、生成整改责任与期限」偏内部口吻。
- 「我的」页底部「退出登录」和顶栏「退出」重复（桌面）。
- 获客工具页副标题「老板的日常武器库」；下达任务页说明条一行里塞了 5 个箭头流程。
- 开闭店清单的日期控件是浏览器原生样式，和其余输入框不一致。
- 门店排行每家店重复 4 次「没数据」，可合成一句。

## 四、这轮确认没问题的
- 所有页面在 1440 和 390 宽下都没有横向滚动；除 `#/delivery`、`#/settings`（老板无权）外没有控制台报错。
- 店员 / 店长手机版信息密度、状态徽标、排序（被打回 → 逾期 → 今天）都到位，是全站完成度最高的部分。
- 无权限页、空状态、首登改密、上手卡收起后的进度条，前六轮的修复都还在。

## 五、处理结果（2026-11-26，分支 `ux/r7-commercial-polish`）

全部在本机用同一份测试库重新截图复验（四个角色，桌面 + 手机共 62 页，无横向滚动）。

**高优先级 H7-1 至 H7-7：全部已修。**
- 今天页「等我处理的」多一条「N 件派给店员的活已逾期」，「逾期」格子把店员的活算进去并写明口径。
- 老板看板「先处理清单」加「店员交差等您审核」「派给店员的活已逾期」，上排数字注明是 AI 专家的任务。
- 「派出去的活」改名「交给 AI 的活」，页头有去「派给店员」的入口和实时数字。
- 门店排行：要盯的店不发金牌；有分数的店不足 2 家时不排名。
- 逾期徽标统一红色；全站中文标点改全角；`#/delivery` 不带任务号时回任务列表。

**中优先级：**
- M7-1 派活页分「派给店里的人 / 交给 AI 专家」两段。
- M7-2 门店页去掉老板看板入口，`#/boss` 跳驾驶舱，AI 专家明细并入驾驶舱。**例外**：平台管理员仍进老板看板（跨企业切换只有它有），工作台有「各企业看板」入口。
- M7-3 `users.display_name`（库表 v65，只加一列、不回填）；建账号加「姓名」，全站显示姓名。
- M7-4 改密码移到「我的」。M7-5 平台管理员导航：工作台 / 企业 / 后台 / 我的。M7-6 套餐页顺序重排，账单明细默认收起。
- M7-7 截止时间相对写法。M7-8 中转页 6 张卡带实时数字（没有轻量接口的卡片没做）。M7-9 任务卡只露「催一下」，其余进「⋯ 更多」。
- M7-10 清单按项统计。M7-11 零值不带符号。M7-12 日期统一用服务器北京时间。
- M7-13 设计令牌：1px 柔和边框 + 轻阴影，保留暖底、品牌黄、吉祥物。M7-14 导航、中转页卡片、退出、反馈、「拆成任务」换内联 SVG 图标。M7-15 控件高度 40 / 32 两档。M7-16 手机价目表两列列表。M7-17 展示文案统一「AI 专家」。M7-18 登录页主句「老板派活，店员拍照交差，AI 帮您盯着」。
- 低优先级 5 条一并做了。

**没做 / 仍待处理：**
- 按钮和页面标题里的 emoji 大多保留：大量测试按按钮名断言，这轮只换了导航、中转页卡片和看不清的几处。
- 手机团队页每行 4–5 个按钮换行后参差，需收进「更多」。
- 手机上浮动反馈钮会压到今天页右侧按钮；今天页「新进展」通知标题过长（「超时一天多，请过问：…」），同类通知没有合并。

- 驾驶舱没有的老板看板内容（经营指标占位、最近交付动态、巡店六格、近 14 天节奏表）没有并入。
