## 四、下一步建议（3 组可以并行，改动范围不重叠）

### Agent A：成员权限与看到什么（钱 / 死路）
**范围**：`app.js` 的 `knownBalance()`、`costNoteText()`、`NAV_GROUPS` 里卡片的 `show` 条件、`newBrief()` 和 `meetingsView()` 的入口权限判断、商量室的选人列表、`expertsView()` 的成员空状态、`teamView()` 的非管理员分支；后端 `STATE` 里的 balance 字段，以及商量室候选人的过滤。
**先做**：N-01 → N-02 → N-03，然后 N-10、N-16、N-25。
**验收**：用店长账号把完整版每一页走一遍，任何地方都看不到「余额 N 点」，也不会出现「填完了才被 403 拒绝」。

### Agent B：店员和店长手机版 + 团队页
**范围**：`static/staff.js`、`static/staff-admin.js`、`static/login.html`、`app/stafftask.py` 的 todo 和审核接口、`app.js` 的 `tm*` 系列（`tmSendText`、`tmMemberRow`、`tmAllocSummary`）。
**先做**：N-08（审核流）→ N-14、N-15 → N-07、N-11 → N-17、N-23、N-24。
**验收**：老板或店长打回一件活，这件活在列表里一直看得到；店员手机上能看到「已通过」；清单上「做完」和「没做」一眼能分开；复制给店员的文字里有品牌和用途。
