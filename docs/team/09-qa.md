## schema53 最终 QA 证据

日期：2026-08-12
结论：**候选代码门禁 GREEN；独立终审 GO，无确定性 P0/P1。该结论不等于部署授权。**

### 目录、花名册与身份合同

- 10 个非餐饮行业的 V2 决策目录共包含 60 名决策员工、64 个有来源约束的研究来源、
  180 项可计算且绑定证据口径的成功指标。
- 当前目录只允许 active 员工承接新任务；被替换的 V1 非餐饮员工保留为 legacy，
  仅用于解释历史任务，不可重新派活或进修。
- 任务、连续协作和会议成员使用冻结身份解析：除 `emp_idx` 外，同时核对
  `employee_key`、`employee_catalog_version`、`employee_name_snapshot`、
  `employee_dept_key`、`employee_spec_sha256`。字段缺失、版本错配或编号复用均
  fail-closed，不会把旧任务静默切换到当前员工。

### provenance 与决策门禁

- V2 用户材料由服务端生成 canonical `decision_evidence.v1` manifest，绑定 tenant、
  员工目录版本、spec SHA、RI 槽位与内容哈希；客户端不能写入 `evidence_id`、kind
  或 manifest。材料类型固定为 `user_submitted_unverified`，只证明提交归属，不冒充
  已验证事实。
- 单项内容上限 4,000 字，`content + source_name` 合计上限 20,000 字；初次派活、
  followup 合并、幂等重放和扣费前校验使用同一口径。超限或 manifest 篡改在建单/
  扣费前拒绝。
- GO 使用严格 canonical 章节和可见事实行：每个 RI/U 精确对必须独占一行，并带
  PDF 导出后仍可见的事实值、记录类型和日期/时间窗；审批边界与禁止动作使用固定
  机器文本。GO 只表示可进入人工审批，`allowed_side_effects=[]`，不授权系统执行
  改价、采购、放行、删除、下发或其他业务写操作。
- 独立输出编辑入口会重新校验冻结员工与持久化 manifest，再走同一门禁；PDF 导出、
  Word 和知识沉淀读取门禁后的持久化正文，不能通过编辑形成未经门禁的 GO。
