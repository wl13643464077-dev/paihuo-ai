# 派活 升级上线说明（第 0–3 期）

给老板和运维看。本次把"数字员工写内容"的产品升级成**门店 AI 督导 + 获客助手**：
老板把活派给店员，AI 盯执行、验照片、催整改；每天递上该发的获客内容。

适用范围：从 R7（数据库 v57，提交 `304b2a0`）升级到本版本（数据库 v60）。
改动明细可以看 `git log --oneline 304b2a0..HEAD` 和 `tests/test_phase*.py`。

---

## 一、先看这 3 条（不做会出事）

1. **数据库从 v57 升到 v60，不能降级。** 新版本第一次启动就会自动迁移，迁移后旧版本程序会
   拒绝启动（"已拒绝降级启动"）。**上线前必须备份**；要退回旧版本只能"恢复备份 + 切回旧代码"，
   备份之后产生的数据会丢。用简易部署脚本 `deploy/simple/deploy.sh` 会自动在停服那一刻做快照，
   失败自动恢复。
2. **经理/员工账号升级后看不到门店。** 巡店、清单、派给店员都改成"按人分配门店"：
   老板、总监看全部门店；店长和普通员工**只能看分配给自己的门店**，升级时这张分配表是空的，
   他们会看到"老板还没给你分配门店，请联系老板"。**上线当天要通知每个老板**去
   「我的 → 团队与权限」给成员勾选"负责门店"。
3. **Caddy 配置要同步更新。** `/pub/` 不再整目录公开，数字人照片/声音改成应用签发的带过期时间的
   临时链接。服务器上的 `/etc/caddy/Caddyfile` 要换成仓库里新版的 `deploy/Caddyfile`
   （旧的 `handle_path /pub/*` 必须删掉），否则要么临时链接打不开，要么旧文件继续被公开访问。

## 二、对现有客户的影响清单

### 数据与账号

| 变化 | 影响 | 需要谁做什么 |
| --- | --- | --- |
| 数据库 v57 → v60（v58 成员负责门店、v59 支付订单、v60 店员任务/清单/整改指派/成员手机号） | 不可降级 | 运维：上线前备份，见第三节 |
| 门店按成员分配 | 店长/员工升级后看不到任何门店 | 老板：团队页给每个人分配负责门店 |
| 成员新增"手机号" | 企业微信群里 @ 人、短信登录都靠手机号 | 老板：在团队页补上店长、店员手机号 |
| 数据保留期 | 每天凌晨 4:17（北京时间）自动删除：内容审查记录 180 天前的、已读通知 180 天前的、全员广播通知 365 天前的、前端报错 30 天前的。台账类（发布记录、巡店事件）不删 | 需要长期留存的，改环境变量 `CONTENTCREW_RETENTION_<规则>_DAYS` |
| 北京时间换日 | 免费额度、每日限次、"今天"都按北京时间零点换日（以前可能按服务器时区） | 无 |
| 登录防爆破 | 同一账号连续输错密码会越来越慢 | 无；客服遇到"登录变慢"可以解释 |

### 合规整改（默认值变了）

| 变化 | 影响 | 怎么恢复/替代 |
| --- | --- | --- |
| **高风险功能默认关闭**：矩阵自动发布（代管小红书/抖音登录态）、全网抓图配图、视频链接转文字（下载抖音/快手/B站视频）、线索雷达搜索引擎网页抓取 | 关闭后接口返回大白话原因。排队中的自动发布任务会被收口为失败并提示改用"半自动发布"；配图只剩 AI 生成；视频转文字在扣点前就拒绝，提示上传自己的音视频；线索雷达改走正规联网检索（结果可能少一些） | 平台管理员在「后台 → 高风险功能开关」可整体打开或只给某个企业打开。**打开前请评估**：违反平台协议可能封号、图片/视频有版权索赔风险、Cookie 泄露等于账号被接管 |
| **/pub 公开素材改为签名临时链接** | 数字人照片/声音只通过带过期时间的链接给视频厂商拉取（默认 6 小时），公开目录里 30 天前的临时文件自动清理（进行中的任务和素材库文件不删） | Caddy 配置必须同步更新（见第一节第 3 条） |
| **公众号素材图链接带过期时间** | 新生成的链接默认 7 天有效；升级前生成的"永久"链接从新版本第一次启动算起再用 7 天，之后失效 | 老板如果把旧排版里的图片链接用在别处，需要在 7 天内重新排版生成；天数可在后台调整 |
| **数字人需要勾选肖像/声音授权** | 上传照片/录音、克隆声音、开拍前都要勾选授权声明，服务端留痕（谁、何时、哪个素材、声明版本）；HeyGen 标注为境外服务商，老板明确同意后才会用，否则只用国内引擎 | 通知做数字人的老板：确认自己拥有照片/声音的授权（用员工或他人形象要有书面授权） |
| **AI 生成内容标识默认开启** | 发布包文案末尾、Word/PDF/md 导出、公众号排版、成片结尾卡、数字人成片元数据都会带"AI 生成"标识 | 老板在「我的 → 企业档案 → AI 生成内容标识」可改文案、按平台关闭（关闭前请了解各平台和监管对 AI 内容标识的要求） |

## 三、上线前运维必做

- [ ] 读完本说明，确认上线时间窗口（停服通常 1 分钟内，但请选在门店营业低峰）。
- [ ] **备份**：`sudo systemctl start paihuo-backup-simple.service`（或旧体系的
      `paihuo-backup.service`），确认 `/var/backups/paihuo/` 里有刚生成的 `db-*.db`。
- [ ] 确认 `/etc/paihuo/paihuo.env` 已离线另存一份（配置加密密钥丢了，后台填过的所有密钥都读不出来）。
- [ ] 确认磁盘剩余空间 ≥ 数据库大小 × 2 + 2GB。
- [ ] 更新 `/etc/caddy/Caddyfile` 为新版 `deploy/Caddyfile`（换成自己的域名），`caddy validate` 后 reload。
- [ ] 新服务器或想换用简易通道的：按 `deploy/simple/README.md` 装好 `paihuo.service`；
      旧体系服务器切换时先 `systemctl disable --now contentcrew.service`。
- [ ] 演练：`sudo bash deploy/simple/deploy.sh --dry-run --ref <本次提交>`，预检全部通过、
      看到"数据库从 v57 升到 v60"。
- [ ] 正式发布：`sudo bash deploy/simple/deploy.sh --ref <本次提交>`；看到"发布成功"。
- [ ] 通知所有老板：① 去团队页给店长/店员分配负责门店、补手机号；② 高风险功能已默认关闭；
      ③ 数字人需要勾选授权；④ 内容默认带 AI 生成标识。

## 六、出问题怎么退

- 发布过程中失败：`deploy.sh` 会自动"停服 → 恢复停服快照 → 切回旧版本 → 启动"，不用手动处理。
- 上线后才发现问题、需要退回：
  `sudo bash /srv/paihuo/current/deploy/simple/rollback.sh --restore-deploy-snapshot`。
  **注意会丢掉上线之后产生的数据**（新任务、店员上传、充值），换下来的数据库保存在
  `/var/lib/paihuo/data/rollback-quarantine-*`，需要时可以从里面找回。能修就优先修、
  少用回退。
- 详细步骤见 `deploy/simple/README.md「三、手动回滚」`。
